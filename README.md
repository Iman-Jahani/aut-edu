# دفترچه اشتراکی کلاس پایتون — نسخه Next.js

بازنویسیِ حرفه‌ای‌ترِ پروژه‌ی قبلی (`index.html` + `class-23.html` + `admin-5.html`) با
**Next.js 14 (App Router) + TypeScript + Tailwind + Supabase**. همون دیتابیس Supabase
قبلی رو استفاده می‌کنه، پس داده‌های موجودت دست‌نخورده می‌مونه.

## اجرا

```bash
npm install
cp .env.local.example .env.local   # مقادیر پیش‌فرض همون قبلی‌هاست، لازم نیست چیزی تغییر بدی
npm run dev
```

سپس `http://localhost:3000` رو باز کن.

## ساختار پروژه

```
src/
  app/
    page.tsx              صفحه‌ی اصلی (لندینگ + پیوستن/ساخت کلاس)
    class/[code]/page.tsx  فضای کاری کلاس (سلول‌های کد، تیم‌ها، کامنت‌ها)
    admin/page.tsx          پنل مدیریت
    layout.tsx, globals.css
  components/
    ProfileModal, WelcomeModal, TeamPicker, CodeCell, CommentsPanel, ToastProvider
  context/
    AuthContext.tsx         لاگین واقعی Supabase (ایمیل/رمز + گوگل) + نقش + پروفایل
  lib/
    supabase.ts             کلاینت Supabase
    types.ts                تایپ‌های دیتابیس
    utils.ts                توابع کمکی (رنگ تیم، فرمت زمان، هش پین و ...)
    pyodide.ts               اجرای کد پایتون در مرورگر (Pyodide)
supabase/schema.sql          مستندِ ساختار جدول‌ها (برای مرجع)
```

## چیزهایی که کامل پیاده‌سازی شده

- لاگین واقعی (ایمیل/رمز + گوگل)، انتخاب نقش (معلم/دانشجو) و پروفایل (اسم + آواتار)
- ساخت کلاس / پیوستن با کد کلاس / اشتراک لینک
- تیم‌ها: ساخت، پیوستن، خروج، لیست اعضا
- سلول‌های کد با CodeMirror، اجرای پایتون با Pyodide، ذخیره‌ی خودکار، حذف
- برچسب‌گذاری (تگ) روی سلول‌ها
- کامنت روی سلول‌ها
- به‌روزرسانی زنده‌ی سلول‌ها با Supabase Realtime
- **تمرین‌ها**: ساخت/ویرایش/حذف توسط معلم (با چند تست‌کیس ورودی/خروجی)، حل توسط
  دانشجو با اجرای واقعی پایتون روی هر تست، نشان‌دادن نتیجه‌ی تک‌تک تست‌ها، بج
  تعداد تمرین‌های حل‌نشده، و صفحه‌ی «پاسخ‌ها» برای معلم با جزئیات کد هر دانشجو
- **کتابخانه‌ی تمرین‌های مشترک**: ذخیره‌ی تمرین در کتابخانه، جستجو و انتخاب از
  کتابخانه هنگام ساخت تمرین جدید، حذف از کتابخانه
- **کوییز زنده**: معلم سوال چندگزینه‌ای می‌سازه (با زمان محدود)، «شروع» می‌کنه؛
  همون لحظه یه بنر شناور با شمارش معکوس برای همه‌ی دانشجوها ظاهر می‌شه (Realtime).
  دانشجو پاسخ می‌ده (یا با اتمام زمان خودکار ارسال می‌شه)، نمره‌ش رو می‌بینه و
  می‌تونه پاسخ‌ها رو مرور کنه. معلم صفحه‌ی «نتایج زنده» داره: رتبه‌بندی زنده،
  میانگین نمرات، تعداد شرکت‌نکرده‌ها، و دکمه‌ی پایان کوییز.
- پنل مدیریت: آمار کلی، جدول کلاس‌ها، جدول تیم‌ها (با رمز عبور ساده مثل قبل)

## یک باگ که در همین مرحله درست شد

توی نسخه‌ی قبلی، وقتی آخرین خط سلول یه عبارت ساده بود (مثل `10 / 2`) و نتیجه‌ش
float بود، Pyodide موقع تبدیل نتیجه به عدد جاوااسکریپت، `.0` رو گم می‌کرد و
`5` نشون می‌داد نه `5.0`. حالا اجرای کد از طریق یه تابع کمکی پایتون (شبیه به
رفتار ژوپیتر/REPL) انجام می‌شه که `repr()` واقعی پایتون رو چاپ می‌کنه، پس
`5.0`, `'text'`, `[1, 2, 3]` و... دقیقاً مثل خود پایتون نمایش داده می‌شن.
(نکته: این یعنی `await` در سطح بالای یه سلول دیگه پشتیبانی نمی‌شه — که در یه
کلاس پایتون مقدماتی به‌ندرت لازم می‌شه.)

- **مسابقه‌ی تیمی**: معلم مسابقه (صورت سوال + زمان) می‌سازه و شروع می‌کنه؛ بنر شناور
  با شمارش معکوس برای همه ظاهر می‌شه. هر تیم یک پاسخ (کد) ارسال می‌کنه که برای
  همه‌ی اعضای تیم قابل‌مشاهده‌ست؛ با اتمام زمان، پیش‌نویس خودکار ارسال می‌شه. معلم
  پاسخ تیم‌ها رو زنده می‌بینه.
- **چت تیمی (جدید)**: هر تیم یه چت خصوصی و زنده داره (دکمه‌ی شناور 💬، بج پیام
  خوانده‌نشده، Enter برای ارسال). جدول `team_messages` لازمه — در `supabase/schema.sql` هست.
- همگام‌سازی زنده‌ی ویرایش هم‌تیمی‌ها روی سلول‌های مشترک تیم
- ظاهر جدید: هدر شیشه‌ای + ناوبری بخش‌ها، انیمیشن مودال‌ها، کارت‌های نرم، لندینگ کامل‌تر

- پیست و drag&drop در همه‌ی ادیتورها (سلول، تمرین، مسابقه) کاملاً غیرفعاله
- دکمه‌ی شناور «سلول جدید» + دکمه‌ی «＋» بین سلول‌ها برای درج در هر جایی؛ اسکرول نرم و هایلایت سلول جدید
- اسکلتون (skeleton) به‌جای متن «در حال بارگذاری» در همه‌ی بخش‌ها، و روی خروجی هنگام اجرای کد

- **input() داخل سلول‌ها**: وقتی برنامه ورودی بخواد، زیر خروجی یه فیلد ظاهر می‌شه (با متن prompt)؛
  جواب رو بنویس و Enter بزن. چون مرورگر نمی‌تونه وسط اجرا منتظر فیلد بمونه، سلول با جواب‌های
  جمع‌شده از اول «بازپخش» می‌شه (`random` با seed ثابت و متغیرهای سراسری بین بازپخش‌ها برگردونده می‌شن).
- **input() در تمرین‌ها**: متن prompt دیگه توی خروجی برنامه نمی‌آد و با خروجی مورد انتظار مقایسه نمی‌شه.
- خطاهای پایتون با traceback تمیز (بدون فریم‌های داخلی) نمایش داده می‌شن.

- **حالت معلم موندگار**: بعد از رفرش صفحه، اگه قبلاً با رمز وارد شده باشی، حالت معلم فعال می‌مونه (تا وقتی خودت خارج بشی) — با `localStorage` نه کوکی سرور، پس فقط روی همون مرورگر.
- **معلم می‌تونه هر سلولی رو حذف کنه**، نه فقط سلول‌های خودش.
- ارتفاع ادیتور سلول‌ها کمتر شد (حداقل ۱۰۰px به‌جای ۲۴۰px).
- **همه‌ی ایموجی‌های رنگی به آیکون (lucide-react) تبدیل شدن** — دکمه‌ها، تب‌ها، بج‌های وضعیت، کارت‌های خالی، پنل مدیریت، لندینگ. یه فیکس CSS سراسری هم اضافه شد تا آیکون‌ها همیشه دقیقاً هم‌ردیف متن باشن (`vertical-align`).
- **آواتار واقعی کاربر** (همونی که توی پروفایل انتخاب کرده) الان کنار اسمش روی سلول‌ها و کامنت‌ها نشون داده می‌شه، نه فقط حرف اول اسم.
- **خروجی/ورودی ipynb** (فقط حالت معلم): دکمه‌ی «ipynb» بالای صفحه‌ی کلاس، یه نوت‌بوک واقعی Jupyter (nbformat v4) از همه‌ی سلول‌های کلاس می‌سازه و دانلود می‌کنه (قابل بازکردن در Jupyter/VS Code/Colab). دکمه‌ی «آپلود» هم یه فایل ipynb می‌گیره و سلول‌های کدش رو (بدون سلول‌های markdown) به‌عنوان سلول‌های جدید (شخصیِ معلم) به کلاس اضافه می‌کنه.
- **پنل مدیریت بازسازی شد**: به‌ازای هر کلاس یه ردیف قابل‌بازشدنه که تیم‌ها (با تعداد عضو و کد)، تمرین‌ها (تعداد پاسخ و پاسخ کامل)، کوییزها (تعداد شرکت‌کننده و میانگین نمره) و مسابقه‌ها (تعداد تیم شرکت‌کننده) رو نشون می‌ده؛ آمار کلی هم شامل تعداد دانشجوهای یکتا (نه فقط تیم/سلول) شد. کوییز/مسابقه‌ی فعال با یه نشان سبز چشمک‌زن مشخصه.

- **لاگین واقعی با نقش (جدید، بزرگ‌ترین تغییر این مرحله):**
  - ثبت‌نام/ورود با ایمیل+رمز عبور، یا با گوگل (`/signup`, `/login`)
  - موقع ثبت‌نام کاربر خودش نقش (معلم/دانشجو) رو انتخاب می‌کنه
  - ورود ناشناس (anonymous) کاملاً حذف شد — هرکی وارد سایت بشه باید لاگین/ثبت‌نام کنه
  - **دسترسی معلمی per-class نه global:** فقط معلم‌ها می‌تونن کلاس بسازن، ولی اگه یه معلم کد کلاسِ یه معلم دیگه رو وارد کنه، به‌صورت پیش‌فرض توی اون کلاس فقط دانشجوئه — مگر اینکه صاحب کلاس از پنل «معلم‌های همکار» (آیکون 🎓⚙️ بالای صفحه‌ی کلاس، فقط برای خودِ سازنده) با جستجوی ایمیل بهش دسترسی معلمی همون کلاس رو بده
  - معلم (مالک یا همکار) یه دکمه‌ی «دیدِ دانشجو» داره که فقط ظاهر صفحه رو عوض می‌کنه (پیش‌نمایش)، نه دسترسی واقعی
  - `/dashboard`: صفحه‌ی اصلی بعد از ورود — «کلاس‌های من (معلم)» با دکمه‌ی ساخت کلاس، و «کلاس‌های من (دانشجو)» با دکمه‌ی پیوستن با کد
  - سیستم قبلی «حالت معلم با پین» کاملاً حذف شد؛ دیگه لازم نیست موقع ساخت کلاس رمز مدیریت بدی

- **جلسات (Sessions) داخل کلاس (تغییر بزرگ این مرحله):** قبلاً همه‌ی سلول‌های یه کلاس پشت سر هم توی یه صفحه بودن. الان هر کلاس شامل چندتا «جلسه» است:
  - صفحه‌ی کلاس (`/class/[code]`) حالا لیست جلساته، نه لیست سلول‌ها
  - معلم (مالک یا همکار) دکمه‌ی «جلسه‌ی جدید» می‌زنه و یه عنوان براش می‌ذاره (مثلاً «جلسه ۳: حلقه‌ها»)
  - هر جلسه صفحه‌ی خودش رو داره (`/class/[code]/[meetingId]`) با همون فضای کار سلول‌های کد که قبلاً داشتیم (تیم، اجرای پایتون، کامنت، تگ، ipynb و ...)، ولی فقط برای همون جلسه
  - تمرین/کوییز/مسابقه و چت تیمی چون بیشتر شبیه فعالیت‌های کل درس هستن، در سطح کلاس موندن (نه مخصوص یه جلسه)
  - دیتای قدیمی خودکار migrate می‌شه: یه «جلسه ۱» برای هر کلاسی که سلول داشته ساخته می‌شه و سلول‌های قبلیش بهش وصل می‌شن (توی اسکریپت SQL پایین هست)
- **پلی‌گراند (Playground):** یه بخش کاملاً جدا و مستقل از کلاس‌ها (`/playground`) که هر کاربر لاگین‌کرده (دانشجو یا معلم) می‌تونه بدون نیاز به هیچ کد کلاسی سلول کد بسازه، پایتون اجرا کنه، ذخیره بشه. سلول‌ها همیشه می‌مونن تا خودِ کاربر پاکشون کنه (مثل یه دفترچه‌ی شخصی).

## قدم بعدیِ پیشنهادی (روی نقشه‌ی راه، هنوز ساخته نشده)

ایده‌ی خوبی مطرح شد: پشتیبانی از درس‌های دیگه (زبان‌های برنامه‌نویسی دیگه، یا ریاضی با یه تخته‌ی گرافیکی زنده شبیه [Ziteboard](https://app.ziteboard.com)). معماری فعلی (جدول‌های جدا برای هر امکان، قابل گسترش) اجازه می‌ده بعداً این‌ها اضافه بشن، ولی خودِ تخته‌ی گرافیکی زنده (کشیدن/اشکال/همگام‌سازی لحظه‌ای) یه فیچر مستقل و بزرگه که باید جدا طراحی و ساخته بشه.

## راه‌اندازی Google OAuth (اختیاری، برای دکمه‌ی «ورود با گوگل»)

اگه نمی‌خوای فعلاً گوگل رو فعال کنی مشکلی نیست، فرم ایمیل+رمز بدون این تنظیمات هم کار می‌کنه.

1. توی [Google Cloud Console](https://console.cloud.google.com/apis/credentials) یه OAuth Client ID از نوع «Web application» بساز.
2. Authorized redirect URI رو بذار: `https://<project-ref>.supabase.co/auth/v1/callback`
3. توی Supabase: Authentication → Providers → Google را فعال کن و Client ID/Secret رو بذار.
4. تو تنظیمات Authentication → URL Configuration، دامنه‌ی سایتت (یا `http://localhost:3000` برای تست) رو به Redirect URLs اضافه کن.

## قبل از اجرا: جدول‌های جدید Supabase

اگر جدول‌های `competitions`, `competition_submissions` و `team_messages` رو نداری،
محتوای `supabase/schema.sql` رو توی SQL Editor اجرا کن. برای چت و بنرهای فوری، Realtime
رو هم روشون فعال کن (خطوط کامنت‌شده‌ی انتهای فایل). بدون Realtime هم کار می‌کنه، فقط
با تأخیر ۱۰ تا ۱۵ ثانیه (polling).

## ایده‌های قدم بعدی

- رتبه‌بندی/امتیازدهی تیم‌ها در مسابقه توسط معلم
- تم تاریک
- ورود واقعی معلم با Supabase Auth به‌جای رمز کلاینتی

## نکات امنیتی (بدون تغییر نسبت به قبل)

- رمز پنل ادمین در `NEXT_PUBLIC_ADMIN_PASSWORD` است و سمت کلاینت چک می‌شه — دقیقاً
  مثل قبل، برای کلاس درسی کافیه ولی امنیت واقعی نیست.
- امنیت واقعی داده‌ها باید از طریق Row Level Security در Supabase تأمین بشه.
